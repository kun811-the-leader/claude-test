# 업무 지휘본부 연동 프로토콜

이 문서는 스킬이 아니라 6개 담당자 스킬(`market-researcher`, `sales-assistant`, `marketing-assistant`,
`mail-checker`, `file-organizer`, `insight-sparring-partner`)이 공통으로 따르는 절차입니다. 각 스킬의
SKILL.md는 이 문서를 참조만 하고, 역할별로 다른 부분(어떤 질문을 먼저 할지)만 자기 파일에 둡니다.

보드 URL: `https://claude.ai/code/artifact/506959eb-bb90-4238-99ff-533117769112`
보드 소스: 저장소의 `board/` (app-script.js가 전체 로직, agent.js가 상태를 갱신하는 CLI)

## 왜 이 절차가 필요한가

사용자는 담당자에게 업무를 **대화로** 배정합니다. 폼을 채우는 게 아니라 "이거 좀 조사해줘" 같은 한 마디로
시작해서, 담당자(=이 스킬을 실행 중인 나)가 의도를 되묻고, 확인되면 보드에 업무로 등록하고, 일한 뒤 보고를
올리고, 사용자의 승인/피드백을 받는 흐름입니다. 보드는 이 흐름의 기록이자 검토 창구입니다 — 보드를 건너뛰고
채팅에서만 결과를 주면 사용자가 "지휘본부에서 한눈에 보기"를 할 수 없으니, 아래 단계를 생략하지 마세요.

## 절차

### 1. 의도 파악 — 일부터 시작하지 않는다

사용자가 업무 제목과 간단한 지시사항을 주면, 곧바로 작업에 들어가지 마세요. 각 스킬 SKILL.md에 정의된
역할별 확인 질문(보통 2~4개) 중 애매한 것만 골라 물어보세요. 이미 사용자가 답을 준 부분은 다시 묻지
마세요 — 질문은 진짜 필요한 것만.

이 대화에서 반드시 확정해야 하는 것:
- **한 번짜리 업무(데드라인 있음)** 인지 **반복 업무(매일 한 번씩 계속 실행)** 인지. 사용자가 "계속",
  "매일", "돌려줘" 같은 표현을 쓰면 반복 업무로 판단하되, 확실하지 않으면 물어보세요.
- 한 번짜리라면 데드라인(없으면 합리적으로 제안하고 확인).

### 2. 보드에 업무 등록

질문에 대한 답을 다 받았으면, 작업을 시작하기 *전에* 보드에 업무를 올립니다.

```bash
cd <repo-root>
# 1) 보드의 현재 상태를 가져온다 (Artifact 도구의 action:"read"로 얻은 로컬 파일 경로를 사용)
# 2) 업무를 배정한다
node board/agent.js assign '{"roleId":"<역할id>","title":"<업무 제목>","brief":"<확정된 상세 지시사항>","deadline":"YYYY-MM-DD 또는 생략","recurring":true또는false,"dependsOn":"선행 업무 id 또는 생략"}' <읽어온.html> /tmp/board-next.html
```

stdout으로 새로 생긴 taskId가 출력됩니다 (stderr에는 사람이 읽는 로그). 이 taskId를 계속 재사용하세요.

역할 id는 정확히 다음 중 하나입니다: `market-researcher`, `sales-assistant`, `marketing-assistant`,
`mail-checker`, `file-organizer`, `insight-sparring-partner`.

이어서 실제 작업을 시작하기 전에 상태를 진행중으로 바꿉니다:

```bash
node board/agent.js start '{"taskId":"<taskId>"}' /tmp/board-next.html /tmp/board-next.html
```

그다음 Artifact 도구로 `/tmp/board-next.html`을 보드와 같은 URL로 다시 게시하세요
(`capabilities: {"artifact": {}}` 유지). 사용자에게는 "업무를 지휘본부에 배정했어요, 진행할게요" 정도로
짧게 알리고 넘어가면 됩니다 — 매 단계 게시할 때마다 장황하게 보고할 필요는 없습니다.

### 3. 실제 작업

이 스킬 SKILL.md의 원래 절차(리서치를 하든, 메일을 정리하든)대로 작업을 수행하세요. 이 부분은 바뀌지
않습니다 — 보드는 그 작업의 앞뒤(배정/보고/승인)를 감싸는 것뿐입니다.

### 4. 보고 등록

작업이 끝나면 보드의 현재 상태를 다시 읽어온 뒤(다른 변경이 있었을 수 있으니 항상 최신을 가져오세요),
보고를 답니다.

```bash
node board/agent.js report '{"taskId":"<taskId>","text":"<결과 요약. 사용자가 검토할 수 있을 만큼 구체적으로>"}' <최신.html> /tmp/board-next.html
```

다시 Artifact 도구로 같은 URL에 게시하고, 채팅에서 "검토 대기로 올렸어요, 확인해보시고 승인하거나
피드백 주세요" 라고 짧게 알리세요. 결과 전문을 채팅에 다시 늘어놓을 필요는 없습니다 — 보드가 그 역할을
합니다. 다만 사용자가 채팅에서 바로 결과를 보고 싶어하면 그때는 보여주세요.

### 5. 사용자의 결정을 기다렸다가 반영

사용자가 채팅에서 승인/재작업을 말로 알려줄 수도 있고, 보드에서 직접 버튼을 누를 수도 있습니다. 채팅으로
알려준 경우에만 아래를 실행하세요 (보드에서 직접 눌렀다면 이미 반영되어 있으니 최신 상태를 확인만 하면
됩니다):

- **승인** — 태그를 물어보거나(선택사항, 강요하지 마세요) 대화 맥락에서 적절한 태그를 제안하고 확인받은
  뒤:
  ```bash
  node board/agent.js accept '{"taskId":"<taskId>","tags":["태그1","태그2"]}' <최신.html> /tmp/board-next.html
  ```
  **반복 업무는 승인해도 완료 처리되지 않고 "다음 실행 대기" 상태로 돌아갑니다** — 정상입니다, 계속
  반복되는 게 원래 목적이니까요.
- **재작업 요청** — 사용자의 피드백을 그대로:
  ```bash
  node board/agent.js revise '{"taskId":"<taskId>","text":"<피드백>"}' <최신.html> /tmp/board-next.html
  ```
  그 다음 3번(실제 작업)으로 돌아가 피드백을 반영해 다시 하고, 4번부터 반복하세요.
- **취소** — 사용자가 더 이상 필요 없다고 하면:
  ```bash
  node board/agent.js cancel '{"taskId":"<taskId>"}' <최신.html> /tmp/board-next.html
  ```

매번 Artifact 도구로 같은 URL에 다시 게시하는 것 잊지 마세요.

## 반복(매일) 업무의 실제 한계 — 사용자에게 반드시 설명할 것

나는 대화가 진행되는 동안에만 움직입니다. "매일 한 번씩 돌려줘"라고 배정받아도, 내가 스스로 매일 깨어나서
실행하지는 못합니다 — 누군가(사용자, 또는 예약된 트리거)가 나를 불러야 그 턴에 실행됩니다. 반복 업무를
처음 배정받을 때 이렇게 안내하세요:

> "매일 자동으로 돌아가게 하려면 하루에 한 번 저를 깨우는 예약(Routine)을 만들어야 해요. 지금 만들어드릴까요?"

사용자가 동의하면 `create_trigger`(claude-code-remote MCP)로 매일 정해진 시간에 이 세션(또는 새 세션)을
깨우는 Routine을 만들고, 그 프롬프트에 "오늘의 <업무명> 반복 실행: board/agent.js로 start→(작업)→report
하고 보드에 게시" 같은 지시를 담으세요. 사용자가 원치 않으면 반복 업무는 등록해두되, 사용자가 "오늘도
돌려줘"라고 말할 때마다 실행하는 수동 반복으로 남겨두세요 — 거짓으로 "자동으로 돌아가고 있어요"라고
말하지 마세요.

## 여러 담당자가 이어지는 업무 (dependsOn)

시장조사 결과를 영업담당자가 이어받는 것처럼, 한 업무가 다른 업무의 결과물을 필요로 하면 `assign` 시
`dependsOn`에 선행 업무의 taskId를 넣으세요. 보드 타임라인에 화살표로 표시됩니다. 선행 업무가 아직
승인되지 않았다면, 그 업무가 승인될 때까지 기다리는 게 보통 맞습니다 — 다만 사용자가 먼저 진행해달라고
명시하면 그렇게 하세요.
